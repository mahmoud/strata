# Dependencies

## Runtime

| Package | Floor | Why |
|---------|-------|-----|
| [boltons](https://github.com/mahmoud/boltons) | `>=20.0.0` | Same author, pure Python, no transitive deps. strata's original `tableutils.py` and `fileutils.py` were the prototypes of `boltons.tableutils.Table` (`ConfigProcessor.to_table`) and `boltons.fileutils.FilePerms` (`validators.FilePath`); it also supplies `strutils.camel2under`/`under2camel` (Variable naming) and `typeutils.make_sentinel`. The floor is the first release with all four on Python 3. |
| [tomli](https://github.com/hukkin/tomli) | `>=2; python_version < "3.11"` | The stdlib `tomllib` backport, for `TOMLFileLayer` on 3.10. Dropped the day the floor reaches 3.11 (`layers.py` does `import tomllib` first). |

Nothing else. `argparse` is stdlib.

### Policy

A new runtime dependency is justified only for a capability strata would
otherwise re-implement, and only if it is pure Python with a maintenance
record. Anticipated, on [the roadmap](roadmap.md):

- [pocket_protector](https://github.com/mahmoud/pocket_protector) for a
  `ProtectedLayer` (secrets), optional extra rather than a hard dependency.
- [face](https://github.com/mahmoud/face) for a richer `CLILayer`, likewise
  an extra.

Runtime floors stay floors (`>=`); pinning is the application's job.

## Development

`[dependency-groups] dev` in `pyproject.toml`: `coverage[toml]`, `pytest`,
`ruff`, `tox`, `tox-uv`. Pinned by `uv.lock`, which is:

- regenerated by `uv lock` (never edited by hand),
- bumped monthly by Dependabot (`.github/dependabot.yml`, grouped PR,
  prefix `chore`),
- verified on every push by the `Lockfile` CI job (`uv sync --locked`, then
  the tests on the locked environment).

The test matrix deliberately resolves dev deps fresh (`uvx --with tox-uv tox`)
so upstream breakage surfaces early; the `Lockfile` job is the counterweight.

## GitHub Actions

Every action is pinned to a commit SHA with a trailing `# vX.Y.Z` comment.
Dependabot updates both (grouped PR, prefix `ci`). Do not hand-edit the SHAs.
Workflow permissions are `contents: read`; only the `publish` job gets
`id-token: write`, and only inside the `pypi` environment.
